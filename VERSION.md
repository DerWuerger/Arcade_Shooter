## Update Rule

`VERSION.md` muss jederzeit den tatsächlich erreichten und freigegebenen Projektstand widerspiegeln.

Regeln:

1. Die Versionsnummer orientiert sich an `ROADMAP.md`.
2. Technische Fertigstellung allein schließt eine Version nicht ab.
3. Unfertige Features erhöhen die abgeschlossene Versionsnummer nicht.
4. Eine technisch fertige Version wird zunächst als Release Candidate oder Awaiting Approval geführt.
5. Eine Version gilt ausschließlich nach ausdrücklicher Freigabe durch Jens Würger als abgeschlossen.
6. Commits, Merges oder erfolgreiche Tests ersetzen diese Freigabe nicht.
7. Ohne Freigabe darf VERSION.md eine Version nicht als Released, Final, Completed oder Approved führen.
8. Nach Freigabe darf der entsprechende Versionsstatus aktualisiert werden.

## Documentation Priority

Alle drei Dateien bilden gemeinsam die zentrale Projektdokumentation.

Priorität bei Konflikten:

```text
1. ARCHITECTURE_CHARTER.md
2. ausdrückliche Entscheidung / Freigabe von Jens Würger
3. ROADMAP.md
4. VERSION.md
5. konkrete Implementierungsdetails
```

Codex darf die Architecture Charter nicht eigenmächtig aufgrund einer Roadmap- oder Implementierungsentscheidung umgehen.
